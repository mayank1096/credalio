What is built, and where to find it

This guide explains the Link 1 design handoff: what it covers, what you received, and how to find your way around it. It takes about five minutes to read.

What is built

Link 1 is the creator’s first journey on Credalio, from sign-up to a first validation. Every screen is designed for desktop and mobile, including empty, error, in-review and success states.

Finding your way around

1 · The prototype (canvas)

Page 1 holds every screen in flow order, grouped under section labels. Each row is a desktop board (1440 wide) next to its mobile board (390 wide).

Press Play to click through the flow. Animations (route line, Nova thinking, confetti, typing) only run in Play mode.

Page 2 holds shared sources. These are not screens; boards on page 1 reuse them with a state (for example a check that is unanswered, right or wrong).

2 · The developer package

index.htmlEvery screen in flow order with desktop and mobile links. Start here.
screens/The code: one responsive .dc.html file per screen, plus the small runtime that renders it.
tokens/Colours, type, radii, shadows, sizes, breakpoints and motion as CSS variables and JSON.
assets/ · fonts/Every image used, and Google Sans.
screens.csvEach screen’s file, its state, and which screens it links to.
README.mdThe detailed reference: latest changes, patterns, rules, breakpoints.
To open it: unzip, then run python3 -m http.server 8000 inside the folder and open localhost:8000. Opening files directly with file:// does not work (browsers block the scripts).

3 · Screen names

CR-AREA-NUMBER, for example CR-KYC-003. Areas: LOG log in, ONB onboarding, DASH dashboard, RDY readiness, KYC identity, CRED credentials, POL policies, ORI orientation, CTR Creator Centre, CREATE start creating, NOT notifications, HOME home pages, COL collaboration, ASG assigned to me, DEC declarations, VAL validation. A trailing letter is a state, such as e error or d done.

Five things to know before you build

  • One file per screen, not per device. Each screen is responsive. The mobile board only previews the same file at 390 wide.
  • States are variants, not copies. A board like CR-KYC-004 just shows CR-KYC-003 in its “verified” state. Build one component with a state prop.
  • Values come from the code. Treat the files as a precise reference for colour, size, spacing, radius, shadow and motion, and rebuild them in your own components. The tokens folder has the shared values.
  • Build these patterns once: the onboarding frame, the dashboard shell (sidebar + top bar), the focus/task shell, the orientation lesson player, the outcome page (success, in review, action needed, failed), Nova’s thinking state, the info tooltip and the field error.
  • Responsive rules: breakpoints at 1080, 960 and 760. Onboarding never scrolls on a laptop (1440×820, 1280×720). Touch targets are at least 44px. All motion turns off with “reduce motion”.

Good to know

LinksButtons that link to another screen work in the prototype. Buttons leading to phase 2 screens are intentionally not linked yet.
Sample dataNames, amounts and dates are examples. Copilot name, Creio balance, readiness, orientation progress and attempts left are dynamic.
NovaThe idea → skills → format steps on the first dashboard and Create something new hand their answers to the Nova chat, which does not ask for them again.
Role pickerAll four roles are selectable. Creator continues to onboarding; Learner, Validator and Organization join a waitlist.
FontGoogle Sans, from Google Fonts. Please confirm its licence before shipping; Google Sans Flex or Inter are the closest alternatives.
