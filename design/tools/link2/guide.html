This guide explains the Link 2 design handoff: what it covers, what you received, and how to find your way around it. It takes about five minutes to read.

What is built

Link 2 is the Creator Studio: everything a creator uses once their work is live. Every screen is designed for desktop and mobile, including empty, error, pending and success states.

Finding your way around

1 · The prototype (canvas)

Every screen sits in flow order under section labels. Each row is a desktop board (1440 wide) next to its mobile board (390 wide).

Press Play to click through. Animations (status tracks, the printing receipt, confetti) only run in Play mode.

The last row holds shared sources. These are not screens; the boards above reuse them with a state (for example a payout method that is pending, connected or needs action).

2 · The developer package

index.htmlEvery screen in flow order, by section, with desktop and mobile links. Start here.
screens/The code: one responsive .dc.html file per screen, plus the small runtime that renders it.
tokens/Colours, type, radii, shadows, sizes, breakpoints and motion as CSS variables and JSON.
assets/ · fonts/Every image used (illustrations, Copilot characters, payout provider logos) and Google Sans.
screens.csvEach screen's section, file, state, and which screens it links to.
README.mdThe detailed reference: sections, patterns, links, open items.
To open it: unzip, then run python3 -m http.server 8000 inside the folder and open localhost:8000. Opening files directly with file:// does not work (browsers block the scripts).

3 · Screen names

CR-AREA-NUMBER, for example CR-PAYO-005. Areas: WAL wallet, PAY payment, REVAL revalidation, EARN earnings, PAYO payouts, COURSE-OV course overview, DISC discussions, CAL calendar, SUP learner support, LRN learners, ANA analytics, PROF profile, ORG organizations, SET settings, AI Nova panel, SEARCH, HELP, NOVA, CREIO Creio, PM account menu, MSG message pop-ups. A trailing letter is a state, such as f failed or p paid.

Five things to know before you build

  • One file per screen, not per device. Each screen is responsive. The mobile board only previews the same file at 390 wide.
  • States are variants, not copies. A board like CR-PAYO-001m just shows CR-PAYO-OUT in its "tipalti" state. Build one component with a state prop.
  • Values come from the code. Treat the files as a precise reference for colour, size, spacing, radius, shadow and motion, and rebuild them in your own components. The tokens folder has the shared values.
  • Build these patterns once: the Studio shell (sidebar + top bar), the focus flow (add Credits, payments, payout method, buy Creio), the outcome page, the status track, the printing receipt, the info tooltip, the Nova panel and the message pop-ups.
  • Responsive rules: breakpoints at 1080, 960 (the sidebar becomes a drawer) and 760. Touch targets are at least 44px. All motion turns off with "reduce motion".

Good to know

LinksButtons that lead to another screen work in the prototype. Buttons that act on the page (Save, Download, Export, Decline) have no screen of their own. Links to Link 1 screens (My Creations, Validation Centre, Notifications, Log in) point to files in the Link 1 package.
Sample dataNames, amounts and dates are examples. Balances, Creio, counts and dates are dynamic.
Creio vs CreditsCreio (AI usage) is always gold with the gold coin. Credits (wallet) always use the cobalt "C" coin.
Open itemsThe client is confirming the MFORGE payment option, payout waiting times, the Tipalti fee claim, the validation decision time and the Creio bundle prices.
FontGoogle Sans, from Google Fonts. Please confirm its licence before shipping; Google Sans Flex or Inter are the closest alternatives.
