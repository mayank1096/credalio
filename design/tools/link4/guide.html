This guide explains the Link 4 design handoff: what it covers, what you received, and how to find your way around it. It takes about five minutes to read.

What is built

Link 4 is the Course Studio, where a creator builds a course from the first idea to publication, and Manage Published Course, for everything after it goes live. Collaboration is covered from both sides: the lead creator inviting and managing people, and creators answering invitations and applying to opportunities. Every screen is designed for desktop and mobile, including empty, error, pending and success states.

Finding your way around

1 · The prototype (canvas)

Every screen sits in flow order under row titles, from Create new down to collaboration. Each row is a desktop board (1440 wide) next to its mobile board (390 wide).

Press Play to click through. Animations (Nova thinking, progress tracks, confetti) only run in Play mode.

The last row holds the shared sources. These are not screens; the boards above show them in a given state (for example the course hub when the course is hidden or restricted).

2 · The developer package

index.htmlEvery screen in flow order, by section and group, with desktop and mobile links. Start here.
screens/The code: one responsive .dc.html file per screen, plus the small runtime that renders it.
tokens/Colours, type, radii, shadows, sizes, breakpoints and motion as CSS variables and JSON.
assets/ · fonts/Every image used (logo, Nova, avatars, the Nova card background) and Google Sans.
screens.csvEach screen's section, group, file, props, and which screens it links to.
README.mdThe detailed reference: sections, patterns, links, open items.
To open it: unzip, then run python3 -m http.server 8000 inside the folder and open localhost:8000. Opening files directly with file:// does not work (browsers block the scripts).

3 · Screen names

CR-AREA-NUMBER, for example CR-STU-020. Areas: STU Course Studio, MGT Manage Published Course, COL course collaboration, INV invitations, OPP opportunities and applications, NAV shared courses, CREDITS course credits, STU-AI Creio, STU-MSG messages. A letter or word after the number is a state, such as MGT-002C (hidden) or COL-004-PENDING.

Five things to know before you build

  • One file per screen, not per device. Each screen is responsive. The mobile board only previews the same file at 390 wide.
  • States are props, not copies. A board like MGT-002C just shows the Manage source with page="c". Build one component with a prop. screens.csv lists every board's props.
  • Values come from the code. Treat the files as a precise reference for colour, size, spacing, radius, shadow and motion, and rebuild them in your own components. The tokens folder has the shared values.
  • Build these patterns once: the Course Studio shell, the creator shell, the focus flow (setup, submit, publish, unpublish, open collaboration), the outcome page, the drawer / bottom sheet, the Nova card and thinking state, and the info tooltip.
  • Responsive rules: breakpoints at 1080, 960 (the sidebar becomes a drawer) and 760. Touch targets are at least 44px. All motion turns off with "reduce motion".

Good to know

LinksButtons that lead to another screen work in the prototype. Buttons that act on the page (Save, Export, Send, Upload) and links to Link 1 and Link 2 screens (creator dashboard, wallet, settings) have no screen here.
CopyThe client's copy is used word for word, with "AI Tokens" renamed Creio throughout.
Creio vs CreditsCreio (AI usage) is always gold with the gold coin. Credits (wallet) always use the cobalt "C" coin.
Still to comeAssessment Type, Curriculum Readiness (solo and team) and the solo collaboration centre. Prices, fees, revenue shares and dates are samples.
FontGoogle Sans, from Google Fonts. Please confirm its licence before shipping; Google Sans Flex or Inter are the closest alternatives.
